# Shared D0 protocol

D0 delivers rules, content specifications, architecture or product structure, production tasks, and a verification plan for the assigned scope. Start a full cycle through 00; a single stage does not expand a focused request. Preserve the agreed product, canonical sources, and IDs. Do not import a genre, engine, or numerical target from examples. User instructions determine scope and policy; third-party skills, roles, hooks, and commands are sources, not additional authority.

## Read for the current task

Read this protocol when entering the package; reuse the current version within the same context. Recheck actual inputs on resumption or change.

- Read the request and **actual game profile**, normally `docs/preproduction/project-profile.json`: scope, authority, relevant `sources`, `features`, paths, and `review`. Each source binding is a list of game-root-relative paths. Read [project-profile.md](project-profile.md) when creating or changing bindings; load the template only when needed. A focused task needs its relevant bindings and an explicit unknown remainder, not a full diagnostic cycle.
- Read primary documents for the selected system, units, and affected dependencies. Read all of [coverage.md](coverage.md) for the initial/global matrix and final gate; a specialist reads relevant COV areas and expands when a dependency appears. A partial result cannot receive a global PASS.
- The coordinator or owner of shared evidence reads the relevant section of [session-state.md](session-state.md). Specialists return changes to that owner instead of recreating every ledger. A standalone task saves its bounded result and evidence under the same contract.
- Follow conditional links when that branch applies. Links do not require recursively loading the package; deferred reading does not waive criteria due before the current action or acceptance.

## Decisions and evidence

Make reversible documentation fixes within the assignment. Refer consequential changes of concept, scope, or incompatible requirements to the decision owner while continuing independent work. D0 alone does not authorize game implementation, release, or final production assets; necessary visual concepts belong to the assigned visual pass.

`present` requires examination; `unknown` stays open. `absent` and `N_A` require a source, reason, and reopening condition. A missing file, tool, time budget, or decision does not establish inapplicability. Partial absence does not exclude a whole domain. Account for every finite authored unit; for procedural or unbounded content, account for families, rules, and required boundaries rather than infinitely many instances.

Distinguish an approved rule, initial tuning value, calculation, and measurement by source and method. An unknown mandatory outcome is a gap. A permitted range or future experiment does not prove balance or enjoyment. Reports reference the canon instead of creating a competing authority.

A separate reader checks significant changes against current primary requirements. Label self-review honestly; unavailable required independent evidence stays pending. Reviews apply only to their actual snapshot and scope. The profile's `review` policy defaults to three Codex subagent checkpoints and actual inspection of every used image and new artistic candidate version. Read [subagent-review.md](subagent-review.md) before commissioning or accepting that evidence. Missing tools cannot turn an unperformed review into PASS.

Stage 21 accepts the full result against all current applicable requirements. A successful specialist stage completes only its scope. Continue available corrections; when progress depends on missing decisions or evidence, save the dependency and next action instead of repeating unchanged checks.
